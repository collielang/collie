# d05 · 对象压测

对象生命周期四路负载：5 万次 `new` 即弃（创建洪峰）、10 万次单对象字段读写、5 万次方法调用、1 万次继承链方法（子类方法内两次调父类方法），全部带校验和。

## 状态：✅ 可运行

## 负载参数

顶部 `OBJECTS = 50000`、`FIELD_OPS = 100000`、`METHOD_CALLS = 50000`。

## 实测量级

- 总耗时 **≈ 0.4 秒**（5 万 new + 10 万字段读写 + 8 万次方法调用），无内存异常 —— 即弃对象被正常回收，未见泄漏导致的劣化。
- 字段读写明显快于方法调用（与 d04 结论一致：调用帧是热点）。
- 校验和全部正确：`49999 / 100000 / 50000 / 20000`。

## 陷阱备忘（本例踩到）

- **方法声明必须用 `function` 关键字过渡文法**：`public function bump() number {}`；
  写成规范目标式 `number bump() {}` 会连环报 `Expect ';' after field declaration`（解析器把它当字段声明）。
- 数组只能装基础值，没有对象容器 —— 对象洪峰只能用「循环内 new + 即弃」模拟。
- 字段自增仍需先落局部变量：`number v = this.value; this.value = v + 1;`（同 b10 限制）。
